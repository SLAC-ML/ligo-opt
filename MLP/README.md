# MLP surrogate: a beginner's walkthrough

An **MLP (multilayer perceptron)** is a neural network made from fully connected
layers. Here it learns to predict optical power from examples generated by Finesse.
PSO uses those predictions to search quickly, then Finesse evaluates the chosen
geometry and supplies more training examples.

## 1. Select the model and start a run

In [`../run.py`](../run.py), set:

```python
SURROGATE_TYPE = "MLP"  # Use "GNN" to select the existing graph network.
RUN_NUMBER = 13         # Choose an unused number within the selected model's folder.
```

Then run from the repository root:

```bash
/home/xuesi.ma/.conda/envs/ligoopt/bin/python run.py
```

Setting the switch to `"MLP"` selects MLP initial training, PSO predictions,
and feedback fine-tuning together. You do not need to
edit the optimizer or rename checkpoints. MLP settings are
`MLP_BASE_TRAINING_PARAMS` and `MLP_FINETUNE_PARAMS` in `run.py`; the original
`GNN_BASE_TRAINING_PARAMS` and `GNN_FINETUNE_PARAMS` configure GNN.
MLP base training runs for 1,000 epochs; GNN base training uses 200.
Both models use 20 epochs per feedback fine-tuning round.

The complete default experiment still runs 100 initial designs and 40 feedback
rounds. This is an experiment, not an instant demo. A fresh run will not overwrite
an existing run's artifacts, and interrupted runs are not automatically resumed.

## 2. Find your way around the code

Read the files in this order:

| File | What it teaches / does |
| --- | --- |
| [`data.py`](data.py) | Turns each saved Finesse graph into four input numbers and one target |
| [`model.py`](model.py) | Defines the layers, activations, and input standardization |
| [`losses.py`](losses.py) | Gives extra attention to small errors near the central power plateau |
| [`training.py`](training.py) | Splits examples, calculates loss, updates weights, saves the best checkpoint |
| [`checkpoint.py`](checkpoint.py) | Saves weights together with scaling, architecture, and detector information |
| [`predictor.py`](predictor.py) | Loads a model and converts its output into powers for PSO |
| [`finetune.py`](finetune.py) | Adapts the previous checkpoint using new Finesse feedback and older examples |
| [`tests/`](tests/) | Small regression checks for data, training, inference, and integration |

Generated files appear in `MLP/data/runN/` and `MLP/models/runN/`. These directories
are ignored by Git; the Python modules, tutorial, and MLP tests are kept as source.

## 3. Understand one training example

Each row has the following inputs, in exactly this order:

| Input | Meaning |
| --- | --- |
| `ITM_Rc` | Input mirror's signed radius of curvature, in metres |
| `ETM_Rc` | End mirror's signed radius of curvature, in metres |
| `q_input_real` | Real part of the input beam's complex q at `ITM.p1.i` |
| `q_input_imag` | Imaginary part of that same q |

The target is `log1p(power)` at the detector selected by `DETECTOR` in `run.py`
(default `p_ITM_p2_i`). `log1p(P)` means `log(1 + P)`: it compresses the power range
and remains well defined at zero. During prediction, `expm1` reverses this transform.

**Why include q?** Your perturbed simulations change mirror curvature while
holding the original design's input beam fixed. Two cavities with the same mirror
curvatures can therefore have different input beams and different powers. The q
inputs tell the MLP which beam is present. For each PSO particle, the shared
optimizer finds its nominal q and reuses it for that particle's four perturbations.

Initial data and feedback remain the existing HDF5 files of simulation graphs.
The MLP loader reads the mirror curvatures, input q, and selected detector power
from each graph. It does not use graph edges. During prediction, features come
directly from a prepared Finesse model; no NetworkX/PyG conversion is needed.

This four-input model assumes the current fixed cavity layout and other fixed
physical settings, including cavity length, laser power, and mirror transmission.
Changing those settings requires matching training data. To vary them within one
model, extend the feature definition and network together, then retrain.

## 4. Follow the numbers through the network

The default architecture in `model.py` is:

```text
4 physical inputs
    → standardize each input column
    → Linear(4, 64) → SiLU
    → Linear(64, 64) → SiLU
    → Linear(64, 1) → Softplus
    → predicted log1p(power)
```

A **linear layer** learns weighted combinations of its inputs plus an offset.
An **activation** adds nonlinearity, allowing curved responses. SiLU is a smooth
activation. Softplus makes the predicted log-power nonnegative, so converting
back to power cannot give a negative physical power.

**Standardization** subtracts each column's training mean and divides by its
training standard deviation. This helps the optimizer handle input columns with
different scales. A constant column uses a scale of one to avoid division by zero.
Those statistics are stored inside the model and reused during prediction and
fine-tuning; they are never fitted on validation examples.

The network has two hidden layers with 64 neurons each. These are starting values,
not a demonstrated optimum. Change `DEFAULT_MODEL_CONFIG['hidden_sizes']` before
a new experiment to try another size. Checkpoints store their own architecture,
so loading a trained model does not depend on later changes to the defaults.

## 5. Understand training and feedback

A **batch** is a group of examples used for one weight update. An **epoch** visits
the training data once. The **loss** measures the difference between predicted
and simulated log-powers. Backpropagation calculates how each weight contributed
to the loss; AdamW uses that information to update the weights. The **learning
rate** controls the update size, and **weight decay** discourages large weights.

Initial nominal/perturbed pairs stay together when splitting training and
validation data. Validation examples do not update the weights or input scaling.
The best monitored validation checkpoint is saved. With only one initial pair,
both examples are used for training and monitoring; that monitoring loss is not
an independent accuracy estimate.

After a PSO search, real Finesse supplies one new nominal example and four fixed-q
perturbations (one example in nominal-only mode). Fine-tuning starts from the
previous checkpoint and trains on every new example plus historical training
examples. The original held-out base pairs stay held out across rounds. Input
scaling stays fixed too. Automatic newest-data weighting uses
`max(1, initial_sample_count / newest_sample_count)` so a small feedback batch
has a useful contribution alongside the older data.

The checkpoint keeps the detector, feature order, model configuration, normalization
buffers, and training split information alongside the learned weights. A checkpoint
for one detector is rejected if PSO asks for another detector.

## 6. Learn the central power plateau more accurately

The Finesse map displays a narrow range, approximately 282.09 to 282.0956.
The saved map also contains much lower powers: the dark color clips values below
282.09. We therefore use the numerical Finesse labels, not pixel colors, to decide
which examples belong near the bright plateau.

`MLP_LOSS_CONFIG` in `run.py` controls the loss in both base training and feedback:

```python
MLP_LOSS_CONFIG = {
    'mode': 'center_focused',   # 'log_smooth_l1' selects the original loss.
    'center_power': 282.09,    # Approximate location of the interesting power band.
    'center_width': 0.01,      # Smooth emphasis falls away outside this band.
    'center_error_scale': 0.001,  # Scale of power errors to pay close attention to.
    'center_weight': 10.0,     # Strength of the extra center term.
}
```

For one sample, let $e=\hat y-\log(1+P)$, where $P$ is its actual Finesse power.
Let $S_\beta(e)$ denote Smooth-L1: $e^2/(2\beta)$ for $|e|<\beta$, and
$|e|-\beta/2$ otherwise. The new loss is

$$
L_i=S_1(e_i)+\alpha\,w(P_i)\,S_{\beta_c}(e_i),\qquad
w(P)=\exp\left[-\frac12\left(\frac{P-P_c}{b}\right)^2\right],
$$

with $P_c=282.09$, $b=0.01$, $\alpha=10$, and
$\beta_c=\log(1+s/(1+P_c))$ for $s=0.001$. This converts the requested power-error
scale into the network's log-power units. Training then averages these per-example
losses with the usual newest-feedback weights. Validation uses the same loss with
unit feedback weights, so checkpoint selection also values the center region.

The first term still teaches the overall curve. The extra term makes tiny errors
near the plateau produce a useful training signal, while its slope remains bounded
for large errors. Membership depends on the **true label**, so a bad prediction
cannot escape the extra penalty by moving outside the band. The target is always
the actual simulated power: the network is not asked to output exactly 282.09.
Any geometry with power in this band receives emphasis, not only a particular ROC
rectangle. There is no extra Finesse simulation or change to the PSO objective.

`center_error_scale` sets loss sensitivity, not a guarantee of that achieved
accuracy. The model remains float32; targets and loss arithmetic use float64 so
rounding the training labels does not discard tiny power differences. Resolving
much finer details may also require more data or a different output representation.

Every checkpoint/log now includes overall **power MAE** and **center power MAE**
(mean absolute error, in the same units as power). For reporting, center examples
satisfy `abs(true_power - center_power) <= center_width`. If no validation examples
fall in the band, center MAE is `None`, rather than a misleading zero. Both base
training and fine-tuning keep these metrics in `training_metadata['history']` and
`training_metadata['best_power_metrics']`, and save the resolved loss configuration.

Optimization, MLP training defaults, and the subspace analysis share
`POWER_DETECTOR = "p_ITM_p2_i"` from `utils/detectors.py`. The notebook rejects
checkpoints and cached maps for another detector. Older Finesse/GNN maps used
`p_ETM_p1_i`; regenerate those maps instead of relabeling their saved values.
New Finesse/GNN map filenames include the detector so older results are preserved.
If the detector or physical settings change, check that the reference band remains
appropriate and that the validation set actually contains center examples.

New training uses this loss automatically. Use a fresh `RUN_NUMBER`, since existing
run artifacts are protected. Existing checkpoints remain usable for prediction,
but do not gain better accuracy until trained further. Standalone fine-tuning
inherits the checkpoint's loss unless explicitly overridden; older checkpoints
without loss metadata retain their original loss by default. To opt an older
checkpoint into this loss, pass `hyperparams={'loss': {'mode': 'center_focused'}}`
alongside the other desired fine-tuning settings. A partial override preserves the
checkpoint's remaining loss settings.

## 7. Inspect results and check quality

The result file is `MLP/data/runN/final_result.pkl`. Use `costs_surrogate`,
`powers_surrogate`, and `evaluations_surrogate` to write analysis that works for
either network. MLP runs also expose `costs_mlp`, `powers_mlp`, and `evaluations_mlp`;
GNN runs retain the existing `*_gnn` names. The `*_finesse` entries are unchanged.
The saved `metadata.json` identifies the selected model and training settings.
Existing GNN-specific cost-map scripts still load GNN checkpoints.

MLP inference still uses Finesse construction/beam tracing to obtain q; it replaces
the full optical power simulation. Unstable or untraceable cavities return exactly
zero power. A successful beam trace does not guarantee that a later full lock and
power solve will succeed, so Finesse feedback remains necessary.

Evaluate power accuracy, the perturbation cost, elapsed time, and the actual
Finesse cost at the geometry PSO chooses. Accurate average powers alone do not
ensure accurate small power differences. The default model and learning rates
are a baseline to compare with GNN, not a claim that MLP is more accurate.

Run the focused checks from the repository root:

```bash
/home/xuesi.ma/.conda/envs/ligoopt/bin/python -m unittest discover -s MLP/tests -p 'test_*.py' -v
```
